radv: RADV_VICTORY_CU_MODE, a workaround that runs compute which syncs storage memory at a workgroup barrier in CU mode

For Mesa 26.2.6 (git apply / patch -p1 at the top of a Mesa checkout). Not a RADV bug fix: see scripts/linux/README.md.

+   /* Victory (local workaround, not a RADV fix): compute in CU mode, a workgroup's waves on one CU. A translated
+    * console shader whose lanes depend on the console's in-wave order across a group barrier (a race in the
+    * translation) then runs in the order the console and AMDVLK give; in WGP mode it does not. RADV's barriers are
+    * correct (standalone tests with storage and texel buffers find no stale reads either way).
+    * RADV_VICTORY_CU_MODE=1: shaders with a workgroup-scope acquire over storage memory; =2: every compute shader. */
+   if (stage == MESA_SHADER_COMPUTE) {
+      const char *cu = os_get_option("RADV_VICTORY_CU_MODE");
+      int mode = cu ? atoi(cu) : 0;
+      if (mode >= 2 || (mode == 1 && info->cs.syncs_storage_in_workgroup))
+         return false;
+   }
